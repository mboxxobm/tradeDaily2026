# トレード日誌作成：データ取り込み手順書・要件定義

- 作成日：2026-11-01（JST）
- 種別：日誌に情報を取り込むための手順書・要件定義（**日次日誌そのものではない**）
- 対象：日本株デイトレードの日次記録と事後検証
- 状態：要件メモ（データ連携・自動取得の実装完了を意味しない）

## 1. この手順書の位置づけ

このファイルは `diaries/JOURNAL_REQUIREMENTS.md` に書かれた共通要件を、実際に日誌へデータを収集・照合・表示する際の作業手順として具体化するもの。各日の実況や実際の約定結果はここに記入しない。

保存先：実際の日誌は `diaries/YYYY-MM-DD/diary_YYYYMMDD.md`（JST）。この手順書は日付に左右されない恒久的な仕様として使用する。

## 2. 目的

売買記録だけでなく、エントリー前後の市場環境、板・歩み値、チャートを同じ時系列で参照できる日誌を作る。
後から「その時点で何が見えていたか」を再現し、判断と結果を検証できることを重視する。

## 3. 収集データソース

| 分類 | データソース | 取得する情報 |
| --- | --- | --- |
| 実取引 | 松井証券のCSV | 約定・売買履歴など |
| Paper Trading | TradingViewのペーパートレード | デモ／ペーパーの取引履歴 |
| 市場データ | 日経平均の1分足ソースデータ | 時刻別の価格推移、各足の終値 |
| 板・歩み値 | 株ステーション、ブリスケ等 | 個別銘柄の板読み・歩み値データ |
| チャート画像 | OneDrive内の当日の日付フォルダ／ファイル | その都度レイアウトしたTradingView画面のスクリーンショット |

**取り扱いの原則**

- 実取引、Paper Trading／デモ、未実行の検討案を混同しない。
- CSVなどの一次資料、本人の口述、推定・分析を区別する。
- 同じ日付（JST）、銘柄、時刻に紐付けて照合する。
- 元のCSV・板データ・画像は改変せず、日誌から参照できる形で関連付ける。
- チャート画像は単に所在を書くのではなく、**日誌内でその場面に対応する画像を表示できる形で取り込む**（画像の添付、または継続してアクセスできるリンクとMarkdown画像埋め込み）。元画像のOneDrive上の保存先も記録する。
- OneDrive・証券会社・TradingView等への実際の接続可否は別途確認する。現段階では取得済みとみなさない。

### OneDriveスクリーンショットの取り込み手順（要件）

1. 日誌対象日（JST）と一致するOneDriveのチャートフォルダー、または該当ファイルを探す。
2. TradingViewでその都度レイアウトしたスクリーンショットを取得する。
3. 画像の撮影・保存時刻、対象銘柄、チャートの時間足、前後のイベントとの対応を、画像・ファイル名や視認できる情報から確認する（推測のみで断定しない）。
4. 9時台、エントリー直前、エントリー10分後、11:30、15:30の該当セクションに画像を取り込み、表示する。該当画像がない時点は「画像未取得」とする。
5. OneDriveの元画像は保持する。GitHubへ画像ファイルも複製する場合は、容量やアクセス権、公開範囲を確認してから実施する（本リポジトリは公開設定）。

## 4. 日誌作成時の取り込み手順

1. **対象日の決定**：日本時間の日付を決め、既存の `diaries/YYYY-MM-DD/diary_YYYYMMDD.md` を読み込む。既存本文は保持する。取引のない休日に空テンプレートだけを作らない。
2. **実取引の照合**：松井証券CSVを参照し、銘柄コード、注文／約定／決済時刻、売買、数量、価格を取得。損益は確実に計算できる場合だけ記載する。
3. **Paper Tradingの照合**：TradingViewのペーパートレード履歴を別ソースとして取得し、実取引と識別したうえで同じ時間軸へ配置する。
4. **指数の取り込み**：日経平均1分足の元データから、イベント前後のOHLC・確定足終値を取得する。日経平均、先物、JP225 CFD等は銘柄・配信系列を区別する。
5. **個別銘柄の板・歩み値の照合**：株ステーション／ブリスケ等の元データから、売買の近傍時刻を照会。板の買い支え・売り圧力・歩み値・出来高を、観測された価格と時刻に結び付ける。
6. **OneDriveの画像取得**：当日の日付のチャートフォルダーか対象ファイルを探す。TradingViewレイアウト画像を選び、銘柄・時間足・撮影日時・画面内の足時刻を確認して、該当時点の欄に埋め込む。単なる画像一覧の末尾添付にはしない。
7. **5時点で時系列化**：9時台のビフォー／エントリー直前／エントリー10分後／11:30前引け／15:30大引けに、価格、参照足、終値の確定状態、出典、対応画像と判断を配置する。複数トレードは取引ごとに繰り返す。
8. **検証・保存**：当時利用できた根拠と事後情報を分け、未取得・不一致・推定を明記する。既存日誌と重複しないよう追記し、保存成功と更新先を確認する。

### 取り込み時の照合キー・品質チェック

- 照合単位：`取引日(JST) + 銘柄コード/系列 + イベント時刻(JST) + データソース`。
- 一次資料の元ファイル名・リンク、タイムゾーン、価格の単位、足の開始／終了時刻を記録する。
- **エントリー直前**には、その時点までに確定した足のみを「確定終値」として採用。未確定足や後から取得したスクリーンショットは明示する。
- **エントリー10分後**の基準は実際のエントリー時刻＋10分。元データに該当時刻がない場合は空欄ではなく「未取得」等とする。
- **11:30・15:30**は日本株のセッション終了時点。時点の1分足終値と前場／日足の終値を混同しない。
- 板・歩み値データにはローソク足の終値がないため、同時刻のOHLCデータと結び付ける。
- 画像をGitHubへコピーする場合は、公開リポジトリであることを踏まえて権利・個人情報・保存容量を確認する。
- どの外部ソースも接続や取得に失敗した場合、取得したふりをせず「未取得」とソース名を日誌に残す。

## 5. 最重要：時系列フォーマット

下記の時点を日誌に必ず設け、**各時点の対象銘柄・日経平均の価格（該当する時間足の終値または時点の観測価格）を、価格種別と基準時刻を添えて記録する**。
実際のデータがない箇所を推測で埋めない。

| 時点 | 記録する内容 | 価格の記載 |
| --- | --- | --- |
| 9時台（ビフォー） | 当日開始時の相場環境・寄り付き状況 | 基準時刻／対応する1分足の終値等 |
| エントリー直前 | エントリー判断の前提、日経平均との整合、板・出来高、チャート | 直前の確定足終値等、参照時刻を明記 |
| エントリー10分後 | エントリー後の値動き、想定との違い、保有／決済状況 | エントリー時刻＋10分に対応する価格・足終値 |
| 前引け（11:30） | 前場終了時の状況 | 前場終値・取得元 |
| 大引け（15:30） | 当日の最終状況 | 当日終値・取得元 |

### 記録上の注意

- 「終値」は、1分足等の**各ローソク足の終値**と、前場／大引けの**セッション終値**を区別する。
- 「9時台」「エントリー直前」「10分後」は対象時刻が変動するため、実際に参照した時刻と足の期間を明記する。9時ちょうどの価格を機械的に終値と呼ばない。
- 約定時刻と1分足の時刻の対応を明示し、取得ソース間に時間差がある場合はそのまま記録する。
- 11:30／15:30の値が未取得なら「未取得」と記載し、終値を創作しない。
- 11:30は前場の取引終了、15:30は大引けの時点として扱い、各銘柄の取引状況や取引日カレンダーに照らして当日の正しい終値を確認する。
- 複数ソースの価格が食い違う場合は取得元と時刻を並記し、都合よく1つに決めない。
- エントリーが複数ある場合は、各エントリーについて「直前」「10分後」を記録する。
- 未エントリーの日も、取得できた9時台・前引け・大引けの状況を記録する。
